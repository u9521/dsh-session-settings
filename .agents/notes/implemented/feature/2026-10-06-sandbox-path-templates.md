# Agent Note: 沙箱目录的场景化快速填充

Status: implemented

## Problem

沙箱面板的「额外可写目录」此前只能逐个手输。而真实场景几乎从不需要单个目录：一次 Rust 构建要 `~/.cargo` 与 `~/.rustup`，一次 Android 构建要 SDK、Gradle 缓存、wrapper、`.android`、Maven 仓库。用户被迫从文档抄路径，抄错一个字符就得到一条静默失效的规则。`skipped` 区块虽会报告失效条目，但那是事后补救：它解释为什么没生效，不降低写错的概率。

## Proposal

面板新增「快速填充」，按技术栈分组，点击把该场景的常用目录连同描述一次性填进草稿。

**纯前端填充，不新增契约。** `src/client/session/sandboxTemplates.ts` 是纯数据加纯函数，不引 React，不新增 HTTP 端点，不改 store schema，不碰 `src/types.ts` 与服务端。填充走面板既有的 `commit()`，因此模板条目与手输条目行为完全一致：同样被 trim、受描述长度上限约束、可逐行编辑删除、保存后无法区分。不设"来源为模板"的标记：保留 provenance 会引出"模板条目是否应随模板更新"的伪问题，而用户要的只是几行可改的初始值。

**按场景分组，不按"本机是否存在"分组。** 模板回答"做这件事通常要放开哪些目录"，不是"这台机器上现在有什么"。区别是承重的：放开某工具链目录的常见动机，恰恰是**该目录将由用户正想跑的那次构建去填充**。从未装过 Android SDK 的机器上 `~/Android/Sdk` 不存在，而那正是该模板最该出现的时候；按存在性过滤会让模板在它变得有用的那一刻消失。`paths.ts` 会丢弃不存在的目录并报进 `skipped`，因此填入尚不存在的路径不会静默出错——这是本方案成立的前提，也是"不改丢弃语义"被列为禁区的原因。

**路径一律写未展开的 `~`。** 客户端没有 home 目录，且是刻意的：`SettingsSnapshotResponse` 不含该字段，预展开 `~` 就得先在客户端发明一个。`~` 由 `server/sandbox/paths.ts` 的 `expandHome` 在服务端展开，这同时让模板不依赖工作区，页面尚未解析出工作区时依然可用。每条路径取工具的文档默认值；`GRADLE_USER_HOME`、`XDG_CACHE_HOME` 等会改写它们，这正是填入的行都保持可编辑的原因。

**描述随路径同表存放，不进 locale 文件。** 描述不是 UI 文案：它随路径进入运行时上下文提示词（`server/sandbox/interceptor.ts` 渲染为 `- "<path>" — <desc>`），是模型读的数据。与所描述的路径同表，路径被改动时其句子不会被遗漏。分组标题则走 locale key，结构（id、路径、顺序）只定义一次，两种语言只提供句子，路径不会在语言之间漂移。

**去重按字面路径比较。** 客户端无法正确规范化：`.` 与相对路径以工作区为基准、`~` 以未知的 home 为基准，任何在此计算的等价关系都可能与服务端实际授权不一致。字面比较只会**漏判**重复（手输过 `/home/me/.cargo` 后再点 Rust 会多一行），可见且可修；"聪明"的比较则可能把两个不同目录判为同一授权。

## Alternatives considered

- **自动探测本机存在哪些目录**：需新增 HTTP 端点与往返。既有 `skipped` 已能如实呈现"配了但不生效"，收益不抵新增契约的成本。
- **一键添加全部模板**：会一次写入二十余条 grant，多数并非用户所需，与本面板"每条 grant 都该有明确用途"的立场冲突。
- **每个目录一个按钮**（而非每个场景一个）：Android 场景需点五次，"快速"就不成立。
- **放宽 `paths.ts` 的丢弃语义**：`bwrap` 的 `--bind` 遇到不存在的路径会让**整条命令**失败（该文件注释已载明），而模板会填入尚未安装的工具目录，放宽是本功能最危险的改动。

## Acceptance criteria

- `custom` 来源下按场景分组渲染模板按钮；点一次填入该场景全部条目（含路径与描述）。
- 只读来源（继承态）下模板区随 add 行一起消失。
- 部分条目已存在时只补缺失的；全部存在时按钮置灰并显示「已添加」。
- 重复点击同一模板无副作用；Android 与 Java 共享 `~/.m2/repository`，叠加不产生重复行。
- 填充只改草稿，需点「保存」才落库；未保存前可逐行删除、编辑。
- 无工作区时模板仍可用；中英双语齐全，分组标题的 locale key 两种语言下都能解析。

## Risks

- **`~/.cache` 是宽授权**：放开整个 XDG 缓存根，范围远超单个工具；`~/.docker` 含 registry 凭据。两者都靠描述写明用途使其可见，若嫌激进可从模板中删除。
- **模板降低授权摩擦**：可能让用户未细看就填入整个场景的目录。缓解是填充仅进草稿、需显式保存，且逐行可见可删。
- **默认路径在 `XDG_*` 被改写的主机上不适用**：缓解是全部可编辑，`pathHint` 已说明 `~` 与相对路径的语义。
- **七个场景不足以覆盖全部技术栈**：靠手输兜底。
