# Agent Note: MCP 资源与提示词只读面板

Status: implemented

## Problem

MCP 服务器除工具外还声明资源与提示词，但本插件从未呈现它们。用户看不到某服务器暴露了哪些资源，也无法在调用前确认提示词模板的内容。

两侧供给不对称：资源由主机 `@deepseek-ai/dsh-mcp-resources` 完整实现（三个共享工具加一个提示段，随每个 profile 挂载），本插件只负责按会话治理；提示词则官方 `dsh-mcp-client` 完全不调用，README 两处写明不支持，调用机制留给他人。两侧都须自行连接才能列举，因为已挂载的官方客户端位于 Cordis fiber 内、无查询接口。

## Proposal

在既有「工具配置」弹窗内增加 资源 与 提示词 两个只读页签，全局与会话入口共用同一套组件。

- **发现**：`tester/collect.ts` 在一次连接内采集工具、资源、模板、提示词与能力位。各 `list*` 隔离失败，单项失败只把对应能力位降级为 false。
- **接口收敛为两个**：`probe` 是唯一探测入口，`remount: true` 才追加重建官方客户端（重连预算耗尽后的恢复路径，缺省**不**重建）；`cache` 是唯一缓存预览入口，只读存储、从不连接。原 `/tools`、`/test` 与之逐字重复、`/refresh` 探测半段相同，四者合并；内容读取不属这两类。
- **读取**：`tester/read.ts` 按需新开短连接执行 `readResource`/`getPrompt`，结果不落盘、不进会话。文本上限 256 KiB 并标记截断；`blob` 只回字节数。
- **模板**：服务端用 SDK 的 `UriTemplate` 解析变量名并展开，客户端不引入 `@modelcontextprotocol/client`（纯净闸门禁止）；展开前校验全部变量非空。
- **缓存**：列表随探测结果持久化到 `mcp_servers.json`，内容永不持久化；读取缓存优先，仅刷新或缓存空时联网。
- **呈现**：打开该弹窗的**入口按钮**改称「服务器信息」（卡片、编辑表单与会话页），弹窗标题与页签标保持原样；内容仍是工具列表。资源按 资源/模板 分组，模板提供变量输入；提示词按 role 分块，并有 分块 / Raw JSON 双视图与复制全文。每行首个动作与重复动作互斥：取得结果后「读取/获取」被带文字的「重新读取/重新获取」取代。
- **一次探测、一次刷新**：同一连接取得全部四类，客户端按 `listsFromResponse` 归一后回填服务器记录与弹窗目标对象。三页签是这一结果的三个视图，故由一个 hook 拥有请求、`loading`、`error` 与 `refresh`；各页签各留按钮但共用实现，任一处点击即整体更新。

## Alternatives considered

- **按资源逐个开关**：主机无按资源策略。`read_mcp_resource` 的 `uri` 可拦，但 `list_mcp_resources` 的结果本插件不经手，被禁资源仍会出现在模型看到的列表里，属半强制。
- **把提示词接入会话**：需值导入 `@deepseek-ai/dsh-llm` 构造 `UserMessage`，打破 Node 半侧不依赖任何 `@deepseek-ai/*`、只用结构类型的既有模式；那是新增主机面能力而非查看器。
- **客户端自行解析模板变量**：纯净闸门禁止在 `src/client/**` 值导入 `@modelcontextprotocol/client`；手写花括号扫描又会与 SDK 的运算符处理不一致。
- **按 URI 判断读取结果归属**：模板在展开前没有 URI 可比，无法让多行共用一份读取状态；改用由请求形态派生的 `targetKey`。

## Acceptance criteria

- 三个页签计数正确；未声明能力与已声明但为空文案不同。
- 打开先读缓存；三页签共用一次刷新。
- 模板填参后由服务端展开；缺变量时按钮禁用且服务端独立拒绝。
- 探测与缓存预览各只有一个入口；缺省探测不重建客户端。
- 读取走独立短连接，不进入模型可见面，不改动按会话策略。
- `pnpm run verify`、`pnpm run fmt:check`、`pnpm run build` 全绿。

## Risks

- **`expand` 静默丢弃变量**：`UriTemplate.expand` 对未提供的变量不报错，`db://{table}/{id}` 会得出形似合法的 `db:///`。故展开前逐名校验并回显缺失名，两侧同规则。
- **空列表歧义**：SDK 对未声明能力返回空列表加警告而非报错，故能力位是区分「未声明」与「声明为空」的唯一依据，不能由长度推断。
- **能力位不算「已播种」**：列表投影剥掉详情数组但保留 `capabilities`，故判断是否还需读缓存时只看**实际条目**；把裸能力位当已加载会跳过缓存读取，对缓存中有列表的服务器误报「声明了但没有」。反之读到的缓存本身若仅有能力位，确意味着「声明了但没有」，该处须计入。两处方向相反且各自正确。
- **旧版 transport 拼写**：存量存储含 `streamable-http-or-sse`，连接器按 HTTP 族处理，未知字符串才拒绝。
- **大资源与重挂载**：文本截断、二进制只报字节数；重建客户端须 `remount: true` 显式触发，缺省探测绝不打断活连接。
- **只读边界**：面板显示能力不放宽模型可见面，模型侧仍由 scope 策略决定，见 [范围原生的 MCP 与技能策略](../architecture/2026-09-30-scope-native-mcp-and-skills.md)。
