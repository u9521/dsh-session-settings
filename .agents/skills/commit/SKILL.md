# 提交

提交是唯一让改动离开工作区的动作，所以这里只管**边界**：一次提交包含什么、信息怎么写、哪些改动必须先问人。

## 一次一件事

一个提交只回答一个问题。重构与行为变更分开，格式化与逻辑分开，机械重写与设计决策分开。

拆分依据是 diff 的**意图**，不是文件数：同一次意图触及 26 个文件仍是一个提交；两个意图落在同一个文件要拆两次。

用户显式要求合并时允许例外，但提交信息末行必须写明来源：

```
Merge refactor and gate tightening for review convenience (user-specified)
```

## 提交信息

- 首行为祈使句，说明做完之后**代码是什么样**，不写"修改了"、"更新了"这类过程词。中文或英文皆可，与相邻历史保持一致。
- 空行后写正文：为什么这样做、否掉了什么、代价是什么。**理由在正文，不在首行**。
- 首行不写 `feat:` / `fix:` 前缀——本仓库按意图而非类型分提交，前缀不携带信息。
- 引用 Note 时写相对路径，不写笔记编号。

## 授权边界

默认可直接改：`AGENTS.md`、`.agents/**`。

改以下路径前必须用 `ask_user_question` 拿到显式同意，并一次性给出**文件、diff 摘要、理由**：

- `src/**`
- `package.json`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`
- `tsdown.config.mjs`、`scripts/build.mjs`
- `.github/**`

边界是职责而不是禁令：本框架只维护脚手架，日常开发是别的预设的事。真需要动这些路径时，说明为什么这次非动不可，并等答复。

## 提交前

1. `git status --short` 看有无意外文件：`.agents/preset/` 的临时产物、`lib/`、日志。
2. 按 [pre-push-checks](../pre-push-checks/SKILL.md) 跑本次改动面需要的最小集合。
3. 只有全绿才 `git add` 与 `commit`。闸门红着提交等于把判别责任推给下一个人。

## 禁止

- 不 `git push --force` 到 `main`；`dist` 分支由 CI 维护，不手工推。
- 不用 `--no-verify` 绕过钩子。
- 不把 `lib/` 或生成产物提交进去。
